===== strudel-embed | findings: 25
Build Oak on the granular npm packages, not the convenience bundles. The core is `@strudel/codemirror@1.3.0` (the `StrudelMirror` class) with `@strudel/core@1.2.6`, `@strudel/transpiler@1.2.6`, `@strudel/webaudio@1.3.0` (which pulls in `superdough@1.3.0` and `supradough@1.2.4`), `@strudel/draw@1.2.6`, `@strudel/mini`/`@strudel/tonal@1.2.6` and `@strudel/soundfonts@1.3.0`. All are AGPL-3.0-or-later. The source now lives at codeberg.org/uzu/strudel; the GitHub repo is archived and labelled "MOVED TO CODEBERG". There has been no npm release since 2026-01-18. The `main` branch has moved on with unreleased breaking changes: `repl({defaultOutput})` becomes `onSchedule(hap,time,cps)` and throws if `defaultOutput` is passed (PR #2138), kabelsalat is removed from core, several reverts landed, and `replaceCode`/`insertCode` were added. Code written against the published 1.2.6/1.3.0 API must use `defaultOutput: webaudioOutput`, and Strudel should sit behind our own adapter. `@strudel/repl` (the `<strudel-editor>` element) and `@strudel/web` are self-contained bundles (2.4 MB and 409 KB) that each carry their own copy of core and CodeMirror. You can't share `@codemirror/state` or `Pattern` with them, add CM6 extensions, or mix them with granular imports without loading core twice. `<strudel-editor>` also has an open bug (#2128, fix PR #2178 still open) where several instances on one page freeze the browser.

`StrudelMirror` gives the most control. It wraps `repl()` from core, a `Drawer` (requestAnimationFrame synced to `scheduler.now()`) and a CM6 `EditorView` exposed as `.editor`. Its constructor options are `root`, `id`, `initialCode`, `onDraw`, `drawContext`, `drawTime`, `autodraw`, `prebake` (required), `bgFill` and `solo`, and everything else is passed through to `repl()`: `defaultOutput`, `getTime`, `transpiler`, `onToggle`, `onUpdateState`, `beforeEval`, `afterEval`, `onEvalError`, `beforeStart`, `editPattern`, `sync`, `setInterval`, `clearInterval`, `mondo`. "Solo" (one editor playing at a time) is built in: starting an editor dispatches a document `start-repl` CustomEvent, and every other mirror stops. There is no option for extra CM6 extensions. Use `view.dispatch({effects: StateEffect.appendConfig.of(ext)})`, or build our own `EditorView` from the exported pieces (`highlightExtension`, `updateMiniLocations`, `highlightMiniLocations`, `flashField`, `widgetPlugin`, `sliderPlugin`, `updateWidgets`, `updateSliderWidgets`) driving a core `repl()` and `Drawer`. The official strudel.cc docs component `website/src/docs/MiniRepl.jsx` is the reference for many small editors on one page. It runs `prebake()`, `loadModules()` and `initAudioOnFirstClick()` once at module level and gives each mirror a unique `id`. It drives custom visuals (a keyboard display) through `editPattern: pat => pat.onPaint((ctx,time,haps,drawTime)=>...)`. That pattern also stops `StrudelMirror` from resetting `drawTime` to `[0,0]`, which it does after every eval when no painters are registered. For our own piano roll and staff renderers, use the `onPaint` hook or our own requestAnimationFrame loop that reads `mirror.repl.scheduler.now()` (cycles) and calls `mirror.repl.state.pattern.queryArc(a,b)`. Haps expose `whole.begin`/`whole.end` (Fractions), `value.note`/`n`/`freq`/`s` and `context.locations`.

Bundler compatibility looks good with one gap. Every AudioWorklet (superdough, supradough, kabelsalat) is inlined as a `data:text/javascript` URL. There is no wasm and no `?url` import in the published dists. The only `new URL(..., import.meta.url)` is the NeoCyclist SharedWorker, used only when `sync: true`, so Vite (the stack Strudel itself uses) and Bun.build should both work. The gap: `process.env.NODE_ENV` is left in the core, superdough and webaudio dists (inside `errorLogger`). Bun's docs don't promise to define it for browser builds, so add an explicit define or a `globalThis.process` shim. Otherwise every runtime pattern error becomes "process is not defined". `@kabelsalat/web@0.4.1` (imported by core 1.2.6) has an IIFE `main` and an ESM `module` with no `exports` map. Browser bundlers resolve it fine, but the Node and Bun runtimes (e.g. `bun test`, server-side checking of exercises) will probably fail on `import {SalatRepl}` unless it is aliased to `dist/index.mjs`. There are no TypeScript types and no destroy/dispose method. The global state (scheduler time and cps functions, `evalScope` globals, `Pattern.prototype.p` injection, the superdough AudioContext singleton, localStorage `codemirror-settings`, `:root` theme variables plus the `dark` class on `<html>`, a fullscreen `#test-canvas`) means our wrapper must serialize evaluations and clean up by hand. No React StrictMode issues have been reported upstream; the double-mount hazards described here are inferred from the source.

===== strudel-headless | findings: 26
Learner code can be graded without audio. The path is: @strudel/transpiler `transpiler()` rewrites the code, then @strudel/core `evaluate()` runs it with `Function()`. Double-quoted and untagged backtick strings become `m(str, offset)` mini calls. Labeled statements `x: expr` become `expr.p('x')`. The resulting Pattern is queried with `pattern.query(new State(new TimeSpan(Fraction(b), Fraction(e))))` or `queryArc(b, e)`. `Pattern.prototype.p` only exists when core's `repl()` injects it. Strudel's own test runtime (test/runtime.mjs) mocks `.p` as identity, so only the last labeled pattern survives there. A grader has to inject its own `.p` collector (copying repl.mjs: `$` gets an index suffix, `_x`/`x_` mutes, an `S` prefix solos) and `stack()` the collected patterns. The alternative is to instantiate core `repl()` with a no-op output and call `evaluate(code, false)`. Tempo is global scheduler state, not part of the pattern. Default cps is 0.5. `setcps`/`setcpm`/`all`/`each` exist only in repl scope, so a grader must stub them and capture the values. A per-hap `cps` control can also change tempo at playback time. Strudel has no bars: by convention setcpm(bpm/beatsPerCycle), so seconds = cycles/cps and beats = cycles*beatsPerCycle.

Environment: core, mini, tonal and transpiler do no DOM, AudioContext or navigator work at import time. speak.mjs wraps its `window` access in try/catch, and the mouse and keyboard listeners check `typeof window` first. All four can run in a module Web Worker. One blocker for Bun and Node: the latest npm release, @strudel/core@1.2.6 (2026-01-17), statically imports `{ SalatRepl }` from @kabelsalat/web@0.4.1. That package's `main` is an IIFE script (`dist/index.js`, type: module, no exports). Node, and the Bun runtime (Bun docs: 'At runtime Bun prefers "main"'), will fail to link the named import. Vite resolves the `module` field, which is why the browser and Strudel's vitest suite work. This was reported as issue #1921 and fixed on Codeberg main by removing kabelsalat from core (PR #1932, 2026-01-18), but no npm release has shipped since. Options: pin the whole family to 1.2.5, which has no kabelsalat dependency, or `bun patch @kabelsalat/web` to point main/exports at dist/index.mjs, or alias it to a stub. Main also renamed `repl({defaultOutput})` to `onSchedule` (passing defaultOutput now throws), split the transpiler into plugins, and fixed voicing `mode:'above'`/`'root'`. The grader should pin exact versions and avoid exact-octave voicing snapshots.

Pitch normalization: use core `valueToMidi(value)` (freq beats note; string note goes through noteToMidi with default octave 3, so 'c' = 48; number note passes through). Do not use `getPlayableNoteValue`, which has a bug. In superdough, `n` is a sample index and never pitch unless `.scale()` turned it into `note`. Synths default to midi 36 and s defaults to 'triangle'. `.bank(b)` makes the sample name `${b}_${s}`. tonal facts: `.scale()` turns {n} into {note:'E3'} strings and tags `context.scale`. `.voicing()` uses iReal-style symbols ('C', 'Am'/'C-', 'C^7'/'CM7', 'Cm7', 'C7', 'Co7', 'Ch7', 'Csus', 'C+'/'Caug'). 'Cmaj7', 'Cdim' and lowercase roots produce silence plus a log line, with no exception. Voicings are 4-5-note piano voicings with doubled notes, so grade on pitch-class sets.

Pin exact versions. superdough provides oscillators (triangle/square/sawtooth/sine + aliases tri/sqr/saw/sin, user via partials, one), supersaw, pulse, sbd, bytebeat, noises (white/pink/brown/crackle), zzfx (z_*), wavetables (wt_*), an 8-operator FM matrix, pitch/vibrato envelopes, and lp/hp/bp filters with ADSR envelopes and LFOs (12db/ladder/24db). Delay and reverb are per-orbit global effects. The reverb is generated algorithmically, so it needs no download. There is no master limiter. The strudel.cc REPL loads everything from strudel.b-cdn.net (CORS *, 30-day cache): Salamander piano (`piano`, 29 MP3s, 5.5 MB, CC-BY 3.0), VCSL (CC0, but multi-GB hi-res WAVs), tidal-drum-machines (71 banks, used via `.bank("RolandTR909")`), uzu-drumkit (default bd/sd/hh…, 2.6 MB, Unlicense), uzu-wavetables, mridangam (CC-BY-SA), a small Dirt-Samples subset (includes `jazz`), plus 125 lazily fetched `gm_*` WebAudioFont soundfonts from felixroos.github.io/webaudiofontdata (CORS *).

Local-first is very feasible. The two sound-source entry points (the `samples()` base URL / `_base` field, and `setSoundfontUrl()`) are the only remote hooks you need to change. AudioWorklets ship inline as data: URLs, so nothing is fetched for them. strudel.cc itself uses a Workbox CacheFirst runtime cache over exactly these hosts. A realistic self-hosted core set (piano, uzu-drumkit, 2–3 drum-machine banks, about 15 GM fonts) is roughly 20–25 MB. For audio-graph access, `getAudioContext()`/`setAudioContext()` and `getSuperdoughAudioController().output.destinationGain` give you a single master GainNode, which you can tap for a recorder, analyser or limiter. Per-pattern analysers come via `.analyze(id)` with `getAnalyserById`/`getAnalyzerData`.

Faster-than-realtime export exists as `renderPatternAudio()` (OfflineAudioContext → WAV). In 1.3.0 it closes the live AudioContext, always forces a browser download, and does not clear the node pools afterwards. That makes it hostile to a coexisting mic detector and to a post-export live session, so Oak should implement its own offline renderer modelled on it, or use realtime MediaRecorder. A mic pitch detector can share superdough's AudioContext if you follow these rules: never force a custom sampleRate (Firefox throws on rate mismatch); use echoCancellation/noiseSuppression/autoGainControl = false; recommend wired headphones (Bluetooth switches to HFP when the mic opens); and re-create the MediaStreamSource whenever the context is swapped. Two integration traps also need handling. First, initAudio() never actually resumes the context because of an operator-precedence bug, so call `resume()` yourself. Second, @strudel/web's dist is a self-contained bundle, so pairing it with @strudel/soundfonts creates two superdough instances and `gm_*` sounds go missing. Use the modular packages instead.

===== pedagogy | findings: 26
Recommended approach: "sound → code → symbol" with three synchronized representations (Strudel code ↔ piano roll ↔ staff). Each concept goes Predict → Run → Investigate → Modify → Make (PRIMM). The Predict step doubles as inner-hearing practice: the learner hums what the code will sound like before pressing play. Teach pitch by scale degree from the start. Hooktheory and the pop/jazz units of Open Music Theory v2 both work this way, and it maps straight onto Roman numerals, Nashville numbers and Strudel's `n(...).scale("C:major")`. One trap: Strudel's scale index starts at 0 (degree − 1), so this must be taught explicitly. Standard notation comes after the sound and code, but it comes early: rhythm notation in unit 1, treble clef in unit 2, key signatures in unit 3, bass clef and the grand staff in unit 5, lead sheets in unit 7. Move minor/Aeolian and the 12-bar blues earlier than classical curricula do, because both are central to the target genres. Teach common progressions as named schemas (four-chord, doo-wop, Aeolian, Mixolydian, blues, ii–V–I). These named chunks are what make chord dictation fast. The proposed core is about 125 concept lessons plus about 12 checkpoints and about 25 capstone sessions (≈160 sessions of 20 min). Advanced tracks add about 75 sessions (jazz harmony ≈34, advanced rhythm ≈20, arrangement & sound ≈20), so ≈235 sessions in total, roughly 10–12 months at 5–6 sessions a week. Milestones: composing simple songs after ≈80 sessions; transcribing diatonic pop (bass, chords, melody) after ≈130–160; transcribing jazz standards and reharmonizing after ≈230. Transcription practice should continue after the last lesson.

Ear training should work inside a key first, in the style of the Functional Ear Trainer: a cadence sets the key, the learner names the scale degree, then sings it resolving to the tonic. Change the key, register and instrument sound on every question. Interval drills come second: teach intervals as distances between scale degrees in a key, and keep isolated-interval drills as a minor deck. Interleave categories once each has been introduced against a contrast. Wong, Chen & Lim 2021 found a robust interleaving advantage for interval learning when singing and reference-song aids were absent. Little et al. 2019 found that alternating practice with passive listening produced learning where continuous practice alone did not. For chord progressions, transcribe the bass line first: sing the bass as scale degrees, infer the roots, then the chord qualities, then the Roman numerals. A 2021 Music Theory Online pilot study supports bass lines plus schemata. Singing should be used daily and graded by microphone pitch detection (pitchy 4.1.0, McLeod Pitch Method). Most drills can be graded automatically: theory facts, scale-degree, interval and chord-quality ID, rhythmic and melodic dictation (compare Strudel events from `pattern.queryArc`, ignoring transposition), harmonic dictation, and singing (cents error). Compositions get rule-based checks plus formative feedback from Claude. Transcriptions of the learner's own audio cannot be strictly graded and are self-checked by A/B playback against the original.

Learning science: use FSRS (ts-fsrs 6.0.0 has a new `DefaultScheduler` API with FSRS-7 as the default) for both facts and perceptual "skill families". Each due perceptual family is reviewed as a short set of freshly generated trials, so the learner never memorizes a single clip. Interleave by default and tell the learner why, because people misjudge blocked practice as better. Use mastery gates (about 85–90%), adaptive difficulty targeting about 85% success, worked examples that fade, and PRIMM / Use-Modify-Create for code. Gamification only helps when rewards carry information. Sailer & Homner's 2020 meta-analysis found small positive effects (g = .49 on learning, .36 on motivation, .25 on behaviour), and expected tangible rewards undermine intrinsic motivation (Deci et al. 1999). In practice: unlocks are real Strudel tools gated by mastery; the skill map decays honestly with FSRS recall probability; the capstone album serves as an identity-building portfolio; every session ends with a saved musical sketch; streaks are forgiving and repairable, because broken streaks reduce later engagement (Silverman & Barasch 2023). Copyright-safe repertoire: in the US, all compositions published in 1930 or earlier are public domain as of 2026, including I Got Rhythm, Body and Soul, Georgia on My Mind, Embraceable You and On the Sunny Side of the Street. Add traditional folk songs, spirituals, blues and ragtime. For modern songs, the learner loads their own audio locally; it is never redistributed and never sent to Claude.
-- RISKS
 * Strudel's `n().scale()` index starts at 0 while scale degrees and Roman numerals start at 1. Without explicit teaching (and 1-based labels in the piano roll and staff) learners will mislabel degrees all the time.
 * Strudel has no notion of meter or bars; tempo is set in cycles. If lessons don't enforce '1 cycle = 1 bar' and setcpm(bpm/beatsPerBar), rhythm notation and Strudel code will disagree.
 * `voicing()` does voice leading automatically and hides inversions and chord spelling. Unlocked too early, it cuts out the learning of voicing by hand.
 * Strudel/iReal chord-symbol conventions (^7, -7, + for aug) differ from common lead-sheet symbols (maj7, m7, Δ). Show both and teach the mapping.
 * Ear-training scores can climb in the app without carrying over to real music (FET users report this). Without real-music tasks and varied instrument sounds, keys and registers, the app will look like it's working when it isn't.
 * FSRS was fitted to flashcard recall, not perceptual learning. Treating a skill family as one card is untested; watch whether daily review load stays inside 20 minutes.
 * ts-fsrs 6.0.0 changed its API (async DefaultScheduler, FSRS-7 default) and declares Node >=24; Bun compatibility is unverified. Tutorials using fsrs()/createEmptyCard() are out of date.
 * Mic pitch detection on untrained adult voices: octave errors, breathy/low-clarity frames, the app's own audio bleeding in without headphones, latency. Grading that is too strict will put a non-singer off; start with tolerant thresholds and fold octaves.
 * Strict mastery gates can frustrate; loose ones produce shallow knowledge. Gate perceptual drills on performance across ≥2 separate days, and never block creative sketching.
 * Gamification can turn into grinding for XP, and streak loss can hurt motivation (Silverman & Barasch 2023). Streaks must be repairable and rewards must carry information.
 * Copyright: the public-domain status is US-only; the user's country may differ (e.g. EU life+70). Modern arrangements of traditional songs and post-1925 recordings are still protected; never ship third-party audio.
 * Lesson content written by Claude can contain musical errors (wrong spellings, mislabelled Roman numerals). Every exercise and answer key needs programmatic checks (e.g. tonal 6.5.1) and render-and-listen QA.
 * Scope: ≈235 authored sessions plus generators is a lot of authoring. Lean on procedural generation for drills and keep the hand-authored content to the concept lessons and capstones.
 * basic-pitch (TF.js) is heavy and imprecise on dense mixes, and essentia.js is stale (0.1.3 from 2022). Grading of the learner's own audio can only ever be hints.
-- RECS
 * Order each concept as sound → code → symbol: hear and play it in Strudel first, then name it, then see it on the staff. Keep code, piano roll and staff synchronized, with highlighting that links them.
 * Use scale-degree numbers (with b/#) as the main pitch language and movable-do syllables (do-based minor) as the singing aid. Teach Strudel's 0-based scale index explicitly as 'degree − 1'.
 * Run each lesson as PRIMM (Predict → Run → Investigate → Modify → Make). Make Predict a hum or sing step to train inner hearing, and make Make produce a saved sketch every session.
 * Teach minor/Aeolian right after diatonic major chords, and pentatonic, blues and the 12-bar form before seventh-chord theory. Treat common progressions as named schemas (four-chord, doo-wop, Aeolian, Mixolydian, blues, ii–V–I).
 * Ear-train in a key first (cadence → scale degree → sung resolution to the tonic), changing the key on every question. Keep interval drills secondary and in-key; transcribe chords bass-line first.
 * Build a transcription ladder from generated loops → public-domain folk songs → public-domain standards (1930 and earlier) → the learner's own audio. Every answer is written in Strudel code so it can be A/B'd against the original.
 * Auto-grade everything that has ground truth: compare Strudel events from `queryArc`, align melodies ignoring transposition, score Roman numerals per chord, measure singing in cents with pitchy. Use Claude only for formative, non-gating feedback on compositions.
 * Use ts-fsrs 6.x (DefaultScheduler, FSRS-7) for facts, and 'skill-family' cards for perceptual drills, each reviewed as a mini-set of freshly generated trials. Interleave by default and show the learner why.
 * Gate units at 85–90% mastery; keep adaptive drills near 85% success; fade worked examples as skill grows (expertise reversal).
