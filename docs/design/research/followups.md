Main result: one bug decides almost the whole matrix, the resolution of @kabelsalat/web. That package has type:module, main=dist/index.js (an IIFE that starts with `var kabelsalat=function(l){...}({})` and exports nothing) and module=dist/index.mjs. Every bundler that targets the browser picks `module`, so all browser rows pass: Vite 8.3.7 dev and build, Bun.build target browser, Bun HTML imports, and Vitest browser mode. Every place that runs node_modules natively picks `main`, so these rows fail at import time with "does not provide an export named 'SalatRepl'": Bun runtime (bun test, a Bun.serve grader), Node (Vitest node externalization) and Vite SSR externalization. Bun.build and the dev server keep the default `true`, so `module` wins there. Upstream fixed it on Codeberg in PR #1932 ("move kabelsalat web to superdough", merged 2026-01-18 22:27 +01:00). ===== claude-tutor-server | findings: 21
For Oak, use the plain Messages API through @anthropic-ai/sdk 1.8.0 (published 2026-11-10), not the Claude Agent SDK. The SDK README lists Bun 1.0 or later as a supported runtime. `new Anthropic()` reads ANTHROPIC_API_KEY, and Bun loads .env files automatically, so the key never needs to be in code. SDK 1.0.0 (2026-10-21; the last 0.x was 0.137.0) moved every request to API version 2026-10-21. That version has four main breaking changes: temperature, top_p and top_k now return a 400; `MessageParam` became a union of user, assistant and system message types; the key is sent as `Authorization: Bearer`; and a client may hold only one credential. To stream to the browser, call `client.messages.stream(params, {signal})`, return either `stream.toReadableStream()` (newline-delimited JSON that the browser reads with `MessageStream.fromReadableStream`) or app-level SSE from an async-generator Response, and call `server.timeout(req, 0)`. Without that call, Bun's default 10-second idleTimeout closes the connection during thinking pauses.

Models (official overview, 2026-11-10): claude-opus-5-5 costs $4/$20 per million tokens (MTok) with a 1M context window and 128K max output. Thinking is always on and default effort is medium. Forced tool_choice `any` or `tool` returns a 400. claude-sonnet-5-5 costs $2/$10. claude-haiku-5-5 costs $0.10/$0.50 for prompts up to 100K tokens and $0.50/$2.50 above that. claude-fable-5-2 costs $8/$40. Recommendations: claude-opus-5-5 for tutoring dialogue (the docs call it the default starting model), and claude-haiku-5-5 at effort `low` with structured outputs for high-volume feedback. The prompt-cache minimum is 512 tokens on all of these models. Cache writes cost 1.25x base input for the 5-minute TTL and 2x for the 1-hour TTL. Cache reads cost 0.05x on Opus 5.5 and Sonnet 5.5 and 0.1x on Haiku 5.5. Render order is tools, then system, then messages. A static prefix of roughly 30–50K tokens (syllabus, a 300-function catalog and the persona) should end in an explicit breakpoint with `ttl:"1h"`, with a top-level automatic 5-minute `cache_control` for the conversation tail. A 1-hour entry before a 5-minute entry is allowed; the reverse is not. Each model has its own cache, so the Opus and Haiku routes cache the prefix separately. Changing `output_config.format` also invalidates the cache, so keep one fixed schema per route.

Tool use: tools are JSON-Schema objects with `strict: true` (all objects need `additionalProperties: false`), `tool_choice` takes auto, any, tool or none and has `disable_parallel_tool_use`, and all parallel `tool_result` blocks go back in one user message. On Opus 5.5 and Sonnet 5.5, use `tool_choice: {type:"auto"}` plus `strict: true`, and use `output_config.format` (SDK helper `zodOutputFormat` with `client.messages.parse` → `parsed_output`) for exercise variants and machine-readable feedback. Strict schemas cannot use minimum, maximum or minLength. Other limits: 20 strict tools, 24 optional parameters and 16 union-typed parameters per request.

The Agent SDK (0.3.322) wraps a native Claude Code binary that runs as a subprocess per session (an idle pre-warmed spare holds about 230–260 MB). Its in-process tools use `tool()` and `createSdkMcpServer()`, and its `executable` option accepts 'bun'. Anthropic's docs say third-party developers may not offer claude.ai login or subscription rate limits in their products, and should authenticate with an API key instead. Given that, the subprocess overhead and the loss of caching control, the Agent SDK is the wrong fit for Oak.
-- RISKS
 * API version 2026-10-21 (SDK 1.x) rejects `temperature`, `top_p` and `top_k` with a 400, so exercise-variant variety cannot come from sampling settings. Use prompt-level variation (seed motifs, explicit constraints) and deduplicate on the server.
 * Opus 5.5 and Sonnet 5.5 return a 400 for a forced tool_choice (`any` or `tool`). Use auto with strict tools, or use output_config.format for JSON-only routes. Haiku 5.5 accepts a forced tool_choice.
 * Bun.serve's default idleTimeout of 10 s closes SSE connections while Opus is thinking silently (display defaults to 'omitted'). Call server.timeout(req, 0) and/or send `: ping` comments.

Each one turns every request into a full-price write with no error.
 * Preserved thinking: trimming or editing earlier turns, or deleting injected reminders, invalidates replayed thinking blocks and the cache. Keep history append-only and send `response.content` back verbatim.

Running it in the Bun server process gives model-generated code access to the filesystem, network and the API key in process.env. Sandbox it (a Worker with no capabilities, an isolated VM, or evaluate in the browser and return the haps).

 * Errors that arrive mid-stream (overloaded_error after HTTP 200) are not retried by the SDK. The relay must surface them and let the UI offer a retry.
 * Haiku 5.5 price jumps 5x (to $0.50/$2.50) once a prompt exceeds 100K tokens. If the cached prefix plus history grows past that, the cheap tier is lost.

I checked everything against the published package source on 2026-11-10: tonal@6.5.1 (released 2026-10-14, MIT), its @tonaljs/* subpackages, @strudel/tonal@1.2.6, @strudel/core@1.2.6 and abcjs@6.7.2 (released 2026-10-16, MIT). The planned pipeline (hap → NotationModel → ABC → abcjs, graded with tonal) is workable. Five facts change the design. (1) Strudel's spelling rules are mostly the same as tonal 6.5.1's. A fresh install of @strudel/tonal pulls @tonaljs/tonal@4.10.0, whose caret ranges resolve to the same @tonaljs/note@4.12.3, scale@4.13.6, key@4.11.4, roman-numeral@4.9.3 and progression@4.9.4 that tonal 6.5.1 pins exactly. Strudel only uses Note, Interval and Scale from tonal, so scale() output is spelled the same way. They differ only in Chord/ChordType (chord 4.10.2 vs 6.2.1: no slash chords, no maj11/-maj7 aliases) and Interval (4.8.2 vs 5.1.1). (2) Strudel's real spelling hazards come from its own code, not tonal. `voicing()` always produces flat-spelled names through its own midi2note, so D^7 gives Gb rather than F#. Notes can be written with 's'/'f' accidentals and default to octave 3; tonal rejects 's'/'f' and returns midi null for a note with no octave. Numeric transpose on note strings goes through Interval.fromSemitones, so a minor 2nd, a diminished 5th or a minor 6th is chosen, and spellings like Fb or Bbb can appear. Strudel's iReal chord symbols are matched against its own voicing dictionary, not tonal. (3) For answer keys: tonal accepts ^7, -7, h7, o7, +, - and bare root symbols. It rejects h9, -add9, -b6, 7susadd3 and 7b13sus, and it also rejects 'ø7' and '∆7'. abcjs displays '^7' as '∆7' (U+2206), turns 'o' into '°' and '0' into 'ø', and prints 'h7', '-7' and 'maj7' exactly as written. So display and grading each need a normalization layer. Progression.fromRomanNumerals ignores numeral case: 'ii7' in C gives 'D7'. Grade by tonic, chroma and bass, not by strings.

(4) abcjs has what Oak needs for code↔notation mapping. The click listener is `(abcElem, tuneNumber, classes, analysis, drag, mouseEvent)`. abcElem has startChar, endChar, el_type, abselem, pitches, duration and `averagepitch` (lowercase). midiPitches is filled in only after `setUpAudio()`. Since 6.7.0 you can write `!class=foo!` before a note and abcjs adds foo to that note's SVG group, but only when `add_classes` is true. That is the most robust way to link note IDs to SVG elements. TimingCallbacks runs on its own performance.now()/requestAnimationFrame clock and has no hook for an external clock. You can only re-seek it with setProgress(sec, 'seconds'), so highlighting should run from Strudel's clock and toggle CSS classes directly. Dragging returns only a step count (`drag.step`, in staff positions); Oak must rewrite the ABC itself and re-render. Tuplets are limited to single digits 2–9 and cannot be nested (open issue #1168 asks for more). Clicks on empty staff space produce no callback, because elements are only hit within 12px. abcjs ships only as a CommonJS/UMD module, about 512 KB minified with the synth included. It has no `exports` or `module` field and its types have no default export. Every DOM access I found in the bundle sits inside a function, so SSR should not crash on import (an inference from a grep).

(5) No maintained JS library takes rational-onset events and produces properly notated ties, tuplets and ABC, so a hand-written quantizer is justified. Options considered:
- @xromdev/notation: 64th-note tick grid, approximate triplets only, pre-1.0.
- musicxml-io: serializes MusicXML and ABC from an already-notated score.
- music21j: beams and MusicXML export; I found no measure or tie generation.
- webmscore: GPL, last published 2023.

VexFlow 5 is better for a click-to-place input staff because it has Stave.getLineForY. Verovio 6.4.1 has the best playback sync (renderToTimemap and getElementsAtTime) and an editing API, but it is about 7.4 MB of WASM under the LGPL. For display plus highlighting, abcjs with `!class=` IDs is sufficient.
-- RISKS
 * Strudel's voicing() always produces flat names (midi2note with the flats table), and numeric transpose can produce Fb, Cb or Bbb. If notation or grading uses value.note strings directly, learners will see 'wrong' spellings (Gb in D major). Re-spell every pitch from MIDI plus key or chord context.
 * tonal rejects Strudel's 's'/'f' accidentals ('cs4', 'ef4') and returns midi null for a note with no octave, while Strudel defaults to octave 3. Without normalization, grading silently fails on empty Note objects.
 * Chord symbols do not round-trip between the three systems. abcjs displays '^7' as '∆' (U+2206), but tonal only knows 'Δ' (U+0394) and '^7'. abcjs shows 'ø' for '0', but tonal has no 'ø7'. Strudel's 'h9', '-add9', '-b6', '7susadd3' and '7b13sus' are unknown to tonal. A learner typing what they see on screen can be marked wrong.
 * Progression.fromRomanNumerals ignores numeral case ('ii7' becomes D7), and toRomanNumerals always outputs uppercase. String comparison of Roman numeral answers will disagree with standard pedagogy.
 * abcjs tuplets are limited to single digits 2–9 and cannot be nested (issues #1168, #1007). Strudel nesting like 'c d [e f g]', or 11+ subdivisions, needs flattening to one (p:q:r ratio or a quantization fallback, or the notation will be wrong or warn.
 * abcjs does not beam by meter, split notes at barlines or add ties automatically. The NotationModel must emit beam-group spacing, tied pieces and ABC bar-scoped accidentals (including =naturals) correctly, or the rendering will be wrong.
 * abcjs startChar/endChar are offsets into the generated ABC string. They change on every regeneration, so prefer stable `!class=oak-e{id}!` IDs, which need add_classes:true and abcjs ≥ 6.7.0. abcElem's shape is documented as 'subject to change', so pin abcjs exactly.
 * TimingCallbacks keeps its own performance.now() clock and will drift from Strudel's scheduler. Don't use it for sync; drive highlights from Strudel time.
 * abcjs is CommonJS-only (about 512 KB minified, synth included) with no tree-shaking. Load it lazily.
 * Open abcjs bugs affect grand staff and wrap (clef changes #1041/#1042, wrap #1070/#1098/#1125, invisible-rest voices #1192). Keep lesson scores simple: fixed staffwidth, explicit line breaks, a single clef per staff.
 * tonal 6.5.0 had a broken dist (index.cjs vs index.js). Pin tonal to 6.5.1 exactly, and expect duplicate @tonaljs/* copies alongside Strudel's 4.x tree (chord, chord-type, interval and core differ in version).
 * Reuse candidates are immature or a poor fit: @xromdev/notation is pre-1.0, a month old and built on a 64th-tick grid; musicxml-io's API is declared unstable. Depending on them would bring fit problems with Strudel's rational rhythms.
-- RECS
 * Pipeline step 1, extract. Run `pat.queryArc(0, loopCycles)` and keep haps where `hap.whole && hap.hasOnset()`. Take onset and duration from whole.begin/whole.end as exact rationals, keeping the fraction.js n/d BigInts; ignore clip/legato. Pitch: if the value is a number it is MIDI; if a string, normalize s→#, f→b, uppercase the letter, add octave 3 when missing, then MIDI = Note.midi(...). Keep `{hapKey, locations: hap.context.locations, s/orbit}` for each event.
 * Pipeline step 2, voices and bars. Assign voices by source (stack layer, `s`, or lesson config). For a piano grand staff, split by register (MIDI < 60 goes to LH) or by layer. Bar index = floor(begin), since 1 cycle = 1 bar. Split events at integer cycle boundaries into tie chains.
 * Pipeline step 3, rhythm. Within each bar, group by beat using TimeSignature.get(meter).type: simple meters use the beat or half-bar, compound meters use dotted-quarter groups. Take the LCD of onset and offset denominators per group. If the beat-relative denominator has an odd factor k > 1, make a tuplet with p = k, q = the nearest lower power of two (2 for 3, 4 for 5–7, 8 for 9), and r = the note count, emitted explicitly as `(p:q:r`. Turn nested tuplets into a single combined ratio when p ≤ 9 (e.g. a triplet inside a triplet becomes (9:8:3). Otherwise fall back to the nearest 1/12 or 1/16 grid and set an `approximate` flag the UI can show.
 * Pipeline step 4, durations. Break each written duration into notatable values (whole, half, quarter, eighth, sixteenth, 32nd, with single and double dots), splitting at beat or half-bar boundaries (e.g. no quarter note straddling the middle of a 4/4 bar) and tying the pieces. Fill gaps with rests. Merge events that share onset and duration into chords [..]; put events with differing durations into extra V: voices.
 * Pipeline step 5, spelling. Take key context from the lesson (tonic + mode → Key.majorKey/minorKey, or Mode.notes(mode, tonic) for modal lessons). For each MIDI note: (a) if its chroma matches a key scale degree, use that scale spelling; (b) otherwise, if a chord symbol is active, use the spelling from Chord.get(sym).notes; (c) otherwise use sharps when going up or when key alteration > 0, and flats when going down or when alteration < 0 (Note.fromMidiSharps / Note.fromMidi). Then apply Note.enharmonic(name, targetPc) to fix octaves (B#3 vs C4, Cb4 vs B3) and Note.simplify to remove double accidentals.
 * Pipeline step 6, ABC emission. Write the header 'X:1', 'M:4/4', 'L:1/16', 'Q:1/4=bpm', 'K:<tonic> <mode abbrev: dor|phr|lyd|mix|loc|m>' (plus '%%score {RH LH}' and 'V:RH clef=treble' / 'V:LH clef=bass' for piano). Emit each note as `!class=oak-e{id}!` + accidental (computed against the key signature and earlier accidentals in the same bar and octave, including '=') + pitch letter with octave marks (AbcNotation.scientificToAbcNotation gives the base token) + length + '-' for ties. Insert spaces at beam-group boundaries. Translate chord symbols for display ('^7'→'maj7' or '∆7', 'h7'→'ø7' via '07', '-'→'m', 'o'→'°'). Record id→{startChar, endChar, hapKeys, codeLocations} while emitting.
 * Rendering. Lazy-load with `const abcjs = await import('abcjs')` and call `abcjs.renderAbc(el, abc, { add_classes: true, responsive: 'resize', foregroundColor: 'currentColor', jazzchords: true, clickListener, selectTypes: ['note'] })`. For dark mode, rely on currentColor and style .abcjs-staff and .abcjs-chord with CSS. Call `visualObj.setUpAudio()` only if you need abcElem.midiPitches.
 * Highlight mapping strategy. Run one requestAnimationFrame loop that reads Strudel's cycle position (I did not verify this scheduler API in this task). Find active NotationModel note IDs with an interval lookup on [begin, end) modulo the loop length, then toggle a class with `svg.querySelectorAll('.oak-e'+id)`. Do not use TimingCallbacks. For the reverse direction, clicking a note: abcElem.extraClass or classes → id → hap.context.locations → select or flash the code range in CodeMirror. Clicking code: cursor offset → events whose locations contain it → add a class to their notes.
 * Transcription input. For v1, build Oak's own pointer layer over the abcjs SVG. Get staff line y-positions from the '.abcjs-staff' and '.abcjs-top-line' boxes, convert y to a diatonic step with STEP = 3.875px × scale, snap x to a beat grid computed from the NotationModel, show a ghost note, and on commit regenerate ABC from the model, never by editing ABC text. If the input staff grows complex (multi-voice, chords), switch that one widget to VexFlow 5 (Stave.getLineForY) and keep abcjs for display.
 * Grading with tonal (pin tonal@6.5.1). First normalize symbols: ∆/Δ→'^', ø→'h', °→'o', '−'→'-', ♭→'b', ♯→'#', 's'/'f'→'#'/'b'. Then use:
- Pitches: Note.get(x).midi or .chroma for sound-equality grading; Note.get(x).name or .pc for spelling-sensitive grading.
- Intervals: Interval.distance(a, b) plus Interval.get(...).num and .q, or Interval.semitones.
- Chords: Chord.get(sym) and compare {tonic chroma, chroma string (pitch-class set), bass} rather than .symbol; Chord.detect(notesBassFirst) for 'name this chord'.
- Keys: Key.majorKey(t).chords / .triads / .chordsHarmonicFunction and Key.minorKey(t).harmonic.chords for diatonic answer keys.
- Roman numerals: RomanNumeral.get(rn) for the degree (.step, .alt). Check quality yourself through Chord.get(Progression.fromRomanNumerals(tonic, [rn])[0]). Never trust numeral case.
- Modes and scales: Scale.get / Mode.get for scale and mode questions.
- Meters: TimeSignature.get for meter classification.
 * Ship a golden test corpus that runs Strudel patterns through queryArc, the NotationModel and ABC. Cover: 'c d e', 'c [d e f]', 'c@3 d', '<c d>', 'c ~ d', ties across bars, quintuplets, nested triplets, voicing() chords in sharp keys, and F#:major scales. Snapshot both the ABC and the spelled pitches, and run with bun test so upgrades of abcjs, tonal or Strudel cannot silently change notation.
 * Pin abcjs to 6.7.2 exactly: `!class=` needs ≥ 6.7.0 and abcElem's shape is unstable. Add ambient typings that extend AbcElem with `extraClass?: string` and the 6th `mouseEvent` argument of the click listener.
-- OPEN
 * What should notation do with rhythms that cannot be expressed in abcjs, such as `.fast(1.1)`, `nudge`, swing, polymeters like '{c d e}%4' that cross bars, or tuplets with p > 9? Show an 'approximate' flag, refuse to notate, or quantize to a grid chosen per lesson?
 * Should the notated length follow whole spans or clip/legato-adjusted durations? (This matters for staccato and legato lessons.)
 * Where does key context come from: always declared by the lesson, inferred (Scale.detect over the bar's pitch classes), or taken from `.scale()` calls (hap.context.scale holds the scale name after scale())?
 * Which Strudel scheduler/clock API should drive highlighting in @strudel/core@1.2.6 (e.g. repl onDraw/onTrigger or scheduler.now())? I did not verify it in this task.
 * For grand-staff piano parts: split hands by register at middle C, by stack layer, or by explicit lesson metadata? Cross-staff beaming is not possible in abcjs.
 * Is it acceptable to add VexFlow 5 (MIT) just for the transcription input widget, or must abcjs be the only engraver for visual consistency?
 * Is Oak's own install guaranteed to resolve @tonaljs/tonal 4.10.0's caret ranges to today's latest 4.x versions (note 4.12.3 etc.)? With Bun this should be enforced and checked through the lockfile.
